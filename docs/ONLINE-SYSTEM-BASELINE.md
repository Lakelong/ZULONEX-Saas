# 线上系统业务基线

核验日期：2026-06-28  
核验环境：`https://boss.zulonex.com` 总部管理后台  
用途：约束体验层改造，避免为了界面简洁而改变业务语义、遗漏字段或放宽权限。

## 改造边界

- 允许调整：信息层级、检索效率、筛选布局、批量操作入口、状态反馈、详情呈现方式。
- 禁止调整：业务对象含义、字段含义、模块归属、流程状态、角色权限、数据范围、接口契约。
- 任何未完成线上核验的字段、状态或权限，均不得标记为“已确认”。
- 演示数据不得复制线上真实姓名、手机号、订单号或支付流水。

## 核心对象结论

### 订单

线上订单与线下订单均明确区分以下对象：

- 学员：订单对应的实际学习服务对象，是操作人员识别订单的主身份。
- 家长：下单或关联监护人。
- 家长手机号：家长联系信息，不等同于学员手机号。
- 经销商、销售方、代下单经销商：三个独立交易参与方。
- 来源、平台、下单方式、渠道：四个不同维度，不得合并成一个“来源”字段。

因此，体验层中禁止再使用“客户”代替“学员”，也不得将家长字段隐藏到无从识别。

### 学员

学员管理线上字段为：学号、学员姓名、性别、出生日期、手机号、就读学校、意向/已选学科、阶段、报名时间、学员状态、创建时间、更新时间、创建人、更新人。

### 家长

家长管理线上字段为：家长姓名、性别、手机号、与学生关系、状态、创建时间、更新时间、创建人、更新人。行内动作是详情、编辑、删除。

## 状态与动作

- 订单页当前已观察到：已支付、待支付、收款确认中、已取消。
- “支付状态异常”属于任务或风险提示，不应覆盖订单自身状态字段。
- 消课动作必须由消课状态和评价状态共同决定，不能为所有记录提供同一组动作。
- 线上仅观察到的状态不能被当作完整枚举；完整枚举仍需结合接口字典和后端代码复核。

## 权限原则

目前原型顶部的“总部运营、交付负责人、商家负责人”只可作为工作视角演示，不能作为正式角色权限配置依据。正式接入前必须以线上角色管理、菜单管理、按钮权限和数据范围配置为准，并逐角色执行回归。

## 上线前门禁

1. `npm run check:business` 必须通过。
2. 每个接入页面必须完成字段、筛选、状态、动作、数据范围五项对照。
3. 所有状态动作必须有可回退结果和失败反馈。
4. 角色切换后必须复核菜单、按钮、数据、脱敏四类权限。
5. 线上真实数据只用于人工核验，不进入原型仓库。
